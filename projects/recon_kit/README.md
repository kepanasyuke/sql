# recon-kit — сверка источника и приёмника

Инструмент после каждой загрузки отвечает на вопрос «данные доехали целиком и без
искажений?». Сравнивает два датасета по ключу и раскладывает расхождения на три
класса: **MISSING** (потеря), **EXTRA** (мусор/устаревшие строки), **CHANGED**
(значения разошлись).

## Что умеет

- потоковое сравнение двух отсортированных наборов (merge-обход, O(1) памяти);
- нормализация значений: `1 234,50`, `1234.5`, `1234.50` — одно и то же число;
  пустая строка и отсутствующее значение сравниваются как `NULL`;
- **checksum-бакеты**: быстрый ответ «идентично» без чтения всех строк
  (`count + сумма хешей` по бакету, не зависит от порядка);
- сравнение подмножества колонок;
- markdown-отчёт с примерами расхождений и exit-код 1 для CI.

## Запуск

```bash
python -m projects.recon_kit.cli run --source source.csv --target target.csv --key client_id
python -m projects.recon_kit.cli run ... --columns turnover,segment --report recon.md --json
```

```
checksum-бакеты совпали (8 шт.): данные идентичны, детальная сверка не требуется
строк: источник 1200000, приёмник 1200000
```

## Зачем бакеты

Полная сверка большой таблицы — минуты. Бакеты по хешу ключа считаются на обеих
сторонах и сравниваются: если 8 бакетов из 8 совпали по количеству и сумме
хешей строк, расхождений нет с точностью до коллизии. Расходятся — запускаем
детальную сверку и видим, в каком бакете проблема (а значит, и в каком диапазоне
ключей искать).

## Тесты

```bash
python -m pytest projects/recon_kit -q
```

Проверяется: нормализация чисел и `NULL`, классификация MISSING/EXTRA/CHANGED,
игнорирование колонок вне выборки, независимость контрольных сумм от порядка
строк, предварительная проверка бакетами и exit-коды CLI.

**В резюме:** «recon-kit — сверка источника и приёмника: потоковое сравнение,
checksum-бакеты, отчёт с примерами расхождений и exit-кодом для CI».
