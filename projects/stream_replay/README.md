# stream-replay — потоковые окна с дедупликацией

## Простыми словами

События приходят потоком и могут дублироваться или опаздывать. Если считать «как
пришло», суммы в отчёте поедут. Инструмент считает агрегаты по окнам времени
события, отбрасывает дубликаты и честно показывает, сколько событий опоздало
безнадёжно.

**Где применяется:** потоковые витрины, разбор расхождений между потоковой и
пакетной загрузкой одной и той же метрики.

**Как запустить:** `python -m projects.stream_replay.cli demo`

Симулятор потоковой обработки: воспроизводит поток событий с доставкой
at-least-once, отбрасывает дубликаты, считает агрегаты по tumbling-окнам и
корректно ведёт себя с опоздавшими событиями.

## Что умеет

- **дедупликация по `event_id`** с ограниченным окном (память не растёт
  бесконечно — вытеснение по FIFO);
- **tumbling-окна** по времени события (а не по времени обработки);
- **водяной знак** `max_ts − allowed_lateness`: окно закрывается само, без
  «подождать ещё немного»;
- **опоздавшие события**: в пределах допуска попадают в своё окно, сильнее
  опоздавшие считаются в `late_dropped` — потеря видна, а не молчаливая;
- **метрики**: получено, дубликатов, опоздавших, окон закрыто, водяной знак;
- **проверка эквивалентности**: при at-least-once (дубликаты) результат окон
  совпадает с exactly-once — это покрыто тестом.

## Запуск

```bash
python -m projects.stream_replay.cli demo
python -m projects.stream_replay.cli demo --events 300 --window 60 --lateness 30 --json
```

## Почему окно по времени события

Если агрегировать по времени прихода, то событие, задержавшееся в сети на две
минуты, попадёт в чужую минуту и исказит оба окна. Время события плюс водяной
знак дают детерминированный результат: одно и то же множество событий всегда
даёт одни и те же окна, независимо от порядка доставки — именно это проверяет
тест на эквивалентность at-least-once и exactly-once.

## Тесты

```bash
python -m pytest projects/stream_replay -q
```

Проверяется: закрытие окна по водяному знаку, `flush` незакрытых окон,
отбрасывание и приём опоздавших событий, вытеснение в дедупликаторе,
эквивалентность результатов при дубликатах и корректность метрик на
сгенерированном потоке.

**В резюме:** «stream-replay — потоковая обработка: tumbling-окна по event time,
водяной знак, дедупликация at-least-once с ограниченной памятью».
