# perf-lab — бенчмарк SQL-вариантов и индексов

Лаборатория, которая отвечает на вопрос «какой из этих запросов быстрее» так,
чтобы ответу можно было верить: сначала доказывается эквивалентность
результатов, потом сравнивается время на одном и том же наборе данных.

## Что умеет

- **корректность как гейт**: каждый вариант считается «правильным» только если
  его результат совпадает с базовым (хеш отсортированных строк); расхождение
  попадает в отчёт и в exit-код;
- **замеры**: прогрев + N повторов, p50 и p95 вместо среднего (среднее врёт при
  выбросах планировщика);
- **сценарии из реальной работы**:
  - последний остаток по счёту — коррелированный подзапрос против `ROW_NUMBER()`;
  - клиенты без активности — `NOT IN` против `NOT EXISTS` против `LEFT JOIN … IS NULL`;
  - топ клиентов за период — seq scan против составного индекса `(client_id, dt)`;
- **управление индексами в сценарии**: `setup`/`teardown` вокруг замера, поэтому
  видно вклад индекса, а не «стало быстрее, потому что что-то ещё изменилось»;
- markdown и JSON отчёты, exit-код 1 при расхождении результатов.

## Запуск

```bash
python -m projects.perf_lab.cli bench --rows 20000 --repeats 5 --markdown artifacts/perf.md
python -m projects.perf_lab.cli scenarios
```

```
| Вариант | p50, мс | p95, мс | Строк | Ускорение | Результат совпал | Примечание |
| correlated_subquery | 12.4 | 14.1 | 300 | 1.0x | да | по одному индексному поиску на счёт |
| window_function | 4.9 | 5.6 | 300 | 2.53x | да | один проход + сортировка |
```

## Почему сначала корректность

Самая дорогая ошибка в оптимизации — ускорить запрос, который считает не то.
Поэтому в лабе нельзя «просто замерить»: если варианты вернули разные строки,
отчёт помечается как невалидный, а CLI возвращает 1. Это же свойство делает
набор сценариев пригодным для регрессии при смене версии СУБД.

## Тесты

```bash
python -m pytest projects/perf_lab -q
```

Проверяется: подготовка данных, совпадение результатов у всех вариантов
сценария, одинаковое число строк у варианта с индексом и без, обнаружение
намеренно расходящихся запросов и структура markdown-отчёта.

**В резюме:** «perf-lab — бенчмарк SQL: эквивалентность результатов как гейт,
p50/p95, вклад индексов, отчёт с ускорением».
