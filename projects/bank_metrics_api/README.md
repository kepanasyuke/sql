# bank-metrics-api — REST API по метрикам клиентов банка

## Простыми словами

Аналитикам и дашбордам нужны цифры по клиентам, но каждому дашборду лезть в базу
напрямую — плохо: нагрузка, права, разная логика расчёта в разных местах. Сервис
отдаёт готовые срезы по HTTP: обороты клиента за период, сводка по портфелю,
статус проверок качества.

**Где применяется:** слой доступа к данным для дашбордов и внутренних сервисов,
тонкий бэкенд под отчётность.

**Как запустить:** `python -m projects.bank_metrics_api.cli serve --port 8765 --self-test`

> **Визуальная схема:** [карта портфолио](../../docs/index.html) — путь SQL-запроса
> в PostgreSQL и место этого проекта в нём.

HTTP JSON API для дашбордов и смежных сервисов: обороты клиента за период,
сводка по кредитному портфелю, статус DQ-проверок. Написан на стандартной
библиотеке (`http.server` + `sqlite3`) — запускается без установки зависимостей,
при этом реализует то, что обычно спрашивают про прод-API.

## Маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | liveness + проверка БД |
| GET | `/clients?segment=&limit=&offset=` | список клиентов с пагинацией |
| GET | `/clients/{id}/turnover?from=&to=` | обороты за период + агрегаты |
| GET | `/portfolio?min_debt=` | сводка по продуктам: долг, утилизация лимитов |
| GET | `/dq` | статусы DQ-проверок, худший статус — в `overall` |

## Что реализовано «как в проде»

- **коды ответов**: 200, 304, 400 (неверные параметры), 404 (нет клиента/маршрута),
  405 (не GET), 500 (ошибка БД) — без «всё 200 с полем error»;
- **валидация параметров**: даты строго `YYYY-MM-DD`, `limit` ограничен 200,
  `from > to` — 400;
- **ETag + 304**: повторный запрос дашборда не тянет тело заново;
- **access-log** одной JSON-строкой (готово к сбору в ELK/Loki);
- **threading-сервер**: параллельные запросы не блокируют друг друга;
- **healthcheck**, отделённый от бизнес-эндпоинтов.

## Запуск

```bash
python -m projects.bank_metrics_api.cli serve --port 8765 --self-test
curl "http://127.0.0.1:8765/clients?limit=3"
curl "http://127.0.0.1:8765/clients/CL001/turnover?from=2026-10-20&to=2026-10-25"
curl "http://127.0.0.1:8765/portfolio?min_debt=10000000"
```

```json
{
  "client_id": "CL001",
  "period": {"from": "2026-10-20", "to": "2026-10-25"},
  "summary": {"days": 6, "debit": 2143520.16, "credit": 1998044.9, "avg_balance": 2833110.55},
  "items": [{"dt": "2026-10-20", "debit": 331225.5, "credit": 288120.0, "balance": 2710044.3}]
}
```

## Тесты

```bash
python -m pytest projects/bank_metrics_api -q
```

Тесты поднимают настоящий сервер на свободном порту и ходят в него `urllib`:
пагинация, фильтр по сегменту, агрегаты против суммы строк, 400/404/405, ETag/304,
`overall` статус DQ считается по худшей проверке.

**В резюме:** «bank-metrics-api — REST API на stdlib: пагинация, фильтры,
ETag/304, валидация параметров, JSON access-log, healthcheck, тесты через
реальный HTTP».
